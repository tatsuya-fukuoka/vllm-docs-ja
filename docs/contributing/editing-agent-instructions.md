# エージェント向け指示の編集 { #editing-agent-instructions }

> `AGENTS.md` およびそこからリンクされているガイドを変更する前に、このページを読んでください。

## トークン予算の意識 { #token-budget-mindset }

`AGENTS.md` はエージェントのリクエストごとに読み込まれ、ドメイン別ガイドは該当領域に入ったときに読み込まれます。
`AGENTS.md` は **200 行未満**、各ドメイン別ガイドは **300 行未満** に保ってください。
ファイルが予算を超えたら、分割するか削るかしてください。収めるために文章を圧縮するのは避けます。

## 内容を追加すべきでない場合 { #when-not-to-add-content }

新しいルールを書く前に、それが本当に必要かを確認してください。

- **エージェントがすでにできている。** まずプロンプトで試してください。ルールがなくてもエージェントが正しく振る舞うなら、追加しないでください。
- **一度きりの事象。** 新しいドキュメントのルールより、コードレベルの修正（lint ルール、CI チェック、テストのアサーション）を優先してください。
- **パスのハードコード。** ファイルパスは変わります。代わりに「X を検索する」という形にしてください。
- **上流のドキュメント。** pytest や ruff などのツールのドキュメントを再掲せず、リンクしてください。
- **既存のルールと矛盾する。** 追加前にリンクされたガイドをすべて検索してください。2 つのルールが衝突する場合は 1 つに統合します。
- **すでに他で扱われている。** `AGENTS.md` とリンクされた全ガイドを検索し、内容が重複していないか確認してください。

上記のいずれかに当てはまる場合は、**その内容を追加しないでください**。

## どこに書くべきか { #where-content-belongs }

目指すのは、スリムな `AGENTS.md` と、コードだけからは学べないことをエージェントに教える充実したドメイン別ガイドの組み合わせです。

| 範囲 | ファイル |
| ----- | ---- |
| プロジェクト全体に共通する不変のルール（コントリビューション方針、環境構築、テスト / lint コマンド、コミット規約） | `AGENTS.md` |
| 領域固有の知識（モデルのパターン、フォーマットの詳細、非推奨化のスケジュール） | ドメイン別ガイド |

**目安:**

- 1 つの領域にしか関係しないなら、ドメイン別ガイドに書いてください。
- すべての領域に関係するなら `AGENTS.md` を検討してください。ただし、エージェントがすでにできていないかをまず確認します。
- 一貫した範囲を共有する自明でない指示が 5 つ以上たまったら、新しいドメイン別ガイドを作成してください。

## 良いドメイン別ガイドとは { #what-makes-a-good-domain-guide }

エージェントがコードや公開ドキュメントから推測できないことを書いてください。標準的なパターンと異なるプロジェクト固有の慣習、複数ファイルにまたがる文脈を必要とする正しい進め方、繰り返し起きるミスへの対処などです。
各項目は短く、具体的で、実行可能にしてください。たとえば、どのファイルに手を入れるか、どの順序で変更するか、どのテストを実行するか、といった内容です。

## ドキュメントをスリムに保つ { #keeping-docs-lean }

- 何かを追加するたびに、周辺の内容に古いものや冗長なものがないかを見直してください。
- 説明よりも例を優先してください。3 行のスニペットは 1 段落の説明に勝ります。
- 関連する箇条書きは、バリエーションを列挙せず 1 つの原則にまとめてください。
- ファイルパスのハードコードではなく `search for X` の形を使ってください。
- PR への参照は、追跡可能性のためドメイン別ガイドでは問題ありませんが、`AGENTS.md` では避けてください。

## アンチパターン { #anti-patterns }

| パターン | 問題 |
| ------- | ------- |
| 事後的な積み増し | 事象ごとにルールを足すだけで削らないと肥大化する |
| ガイド間のコピペ | 重複した内容は次第に食い違う。1 か所にまとめ、もう一方からリンクする |
| 命令の羅列 | エージェントが読み飛ばすほど長い DO NOT のリスト。原則にまとめる |
| 設定のスナップショット | 値そのものではなく、値を取得するコマンドを示す |

## 変更時のチェックリスト { #change-checklist }

エージェント向け指示ファイルへの変更を提出する前に確認してください。

- [ ] **自明でないか?** このルールがなければ、エージェントは誤った動作をするか?
- [ ] **矛盾はないか?** リンクされたガイドをすべて検索して矛盾がないか確認したか?
- [ ] **書く場所は適切か?** プロジェクト全体のことは `AGENTS.md`、領域固有のことはドメイン別ガイドか?
- [ ] **追加の埋め合わせをしたか?** 代わりに何かを削除・統合したか?
- [ ] **予算内か?** `AGENTS.md` は 200 行未満、ドメイン別ガイドは 300 行未満か?
- [ ] **パスをハードコードしていないか?** 変わりうるパスには「X を検索する」形を使っているか?
- [ ] **検証したか?** エージェントが実際に新しい指示に従うことを確認したか?
